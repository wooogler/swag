## 0. 결론 먼저 (권고)

1. **찬성 — 경험 설문(통제감·신뢰·표현력·국소성·예측가능성 지각·커버리지 지각·채택 의향)은 세션 말미로 옮겨, 두 버전을 나란히 놓고 한 번에 받는다.** 근거 다섯:
   - **앵커의 비대칭 해소.** within-subjects에서 첫 블록의 절대 평정("I felt in control" 1~7)은 기준점이 없고, 두 번째 블록에야 비교 대상이 생긴다. 4셀 균형이 이 비대칭을 *편향*으로 만들지는 않지만 *잡음*으로 남긴다 — N=16에서 아깝다. 나란히 놓으면 두 평정이 같은 기준을 공유하고, 상대 판단은 절대 판단보다 안정적이다.
   - **테스트 직후 평정은 결과 평가가 된다.** 방금 8개 응답을 판정한 직후의 "I trust this chatbot"·"I felt in control"은 도구 경험이 아니라 *그 8개의 성적*에 끌린다. 말미로 옮기면 두 버전 다 같은 거리에서 회고하게 된다(둘 다 결과를 본 뒤이므로 대칭).
   - **인터뷰의 발판.** 설문 → 인터뷰 순서면 진행자가 극단·불일치 응답을 짚어 프로브할 수 있다("첫 번째 버전에 '어느 질문이 영향받을지 알았다'를 2점 주셨는데요 — 어떤 상황이었나요?"). 자유서술 2개를 타이핑으로 먼저 받으면 진행자 영향 없는 개인 회고도 확보된다.
   - **시간 중립.** 블록별 2분×2 = 4분 ↔ 말미 ~4분. 블록은 튜토→작업→테스트로 끝나 흐름이 깨끗해진다(파일럿에서 느낀 끊김이 이것이라면 그대로 해소).
   - **선례.** ConstitutionMaker(Petridis et al., IUI 2024)가 정확히 이 형태 — 두 조건을 각 20분 쓴 뒤 **한 번의 post-study questionnaire**를 "With {Tool A/B}, I felt …" 5문항으로 받고 인터뷰로 이어감. 조건 직후 설문(EvalLM·Co-Evolution·InstructPipe·TeachTune)이 다수 관례이긴 하나, 말미 비교 설문도 확립된 선택지다.
2. **단, 부담(B1·B2)은 블록 안에 남기는 것을 권한다.** NASA-TLX는 정의상 과제 **직후** 측정이고(Hart & Staveland 1988), 선례에서도 예외 없이 조건 직후다(EvalLM TLX 5문항 · InstructPipe Raw-TLX · TeachTune 7점 TLX "right after building" · Co-Evolution 블록 직후). 40분 뒤 회고 부담은 다른 construct(회고된 부담)다. **블록 테스트 UI의 마지막 화면에 2문항(~30초)**으로 넣으면 "별도 설문" 느낌 없이 남는다. 이것이 흐름을 해친다고 판단되면 부담도 말미로 — 그 경우 논문에 *retrospective*로 명시한다. RQ 밖 비용 지표라 감당 가능한 손실이다.
3. **말미 설문의 형태.** 두 버전을 나란히 둔(side-by-side grid) 7점 진술 **12개** + 양극 비교 **5개** + 자유서술 **2칸** — 약 4분 [파일럿 실측]. 그 답에서 인터뷰가 출발한다.
4. **RQ 지위는 그대로.** 설문은 어느 RQ의 측정도 아니다(설계 v2.1 §6: '저작 경험의 주관 지표'·'비용 지표'). 그래서 위치를 옮겨도 측정 논리는 흔들리지 않는다 — 옮기기 쉬운 이유이자, 문항을 과하게 불리지 말아야 할 이유. 지각 예측가능성 문항(P1)은 RQ2 실측(V1~V3)과 **병치**하되 *perceived*로 표기한다(Kulesza 2012: 자기평가 이해도는 실측 soundness와 갈림 · Chromik 2021: 결과 확인 뒤 자기평가 하락 — 설계 v2.1 §2 'RQ2 construct'의 논거 그대로).

## 2. 위치의 선택지와 대가

### A. 현행 — 블록별, 테스트 직후
- **+** 즉시성(부담·정서에 특히 중요) · 조건별 독립 평정(블록 단위 측정과 짝이 맞음).
- **−** 첫 블록에 비교 앵커 없음(위 §0-1) · 테스트 결과에 끌린 평정 · 블록 흐름 끊김(파일럿 인상) · 5문항이라 "설문"치고 정보량이 적음.

### B. 세션 말미 일괄 (side-by-side)
- **+** 앵커 공유 · 인터뷰 도입 자료 · 블록이 행동 측정만으로 깨끗(논문 서술: 블록 = 행동, 말미 = 회고) · 문항을 조금 늘려도 한 번이라 부담이 덜함.
- **−** 첫 버전은 40분 뒤 회고 → recency·contrast 효과(부담 문항이 특히 약함) · 85분 시점 피로 → 평정 수 상한 필요(≤ 25~30) · 나란히 놓으면 "어느 쪽이 나은가" 프레임이 명시적 → demand 노출. 다만 이미 인터뷰 Q4가 같은 노출이고 **선택 비율은 보고하지 않는다**는 규율(설계 v2 §7)을 그대로 적용하면 된다.

### C. 하이브리드 (권고)
- 블록 안: **B1·B2만** — 블록 테스트 UI 마지막 화면(~30초).
- 말미: 나머지 side-by-side 12 + 비교 5 + 자유서술 2 (~4분) → 인터뷰(8분).
- 시간: 현행 설문 4분 → 약 5분(+1분). 인터뷰 8분 사수. 세션 ~93분. 넘치면 말미 문항을 §3.3의 "빼도 되는 것"부터 줄인다.

## 3. UIST/CHI 시스템 스터디에서 무엇을 묻는가 — 관례와 이 연구용 문항 은행

### 3.1 도구별 관례와 이 연구에서의 적합성

| 도구 | 관례 | 이 연구 |
|---|---|---|
| **Raw NASA-TLX** (3~5 하위척도) | 부담. 거의 모든 시스템 스터디 | B1(정신적 요구)·B2(좌절) 유지. 원하면 노력(effort) 1개 추가 |
| **7점 자작 진술** (경험 구인 — control, confidence, satisfaction, expressiveness, think-through, collaborative…) | 시스템 논문의 표준. 검증 척도가 아니라는 한계는 관례상 수용 — 구인당 1~2문항, 총 10~12개 | 이 연구의 몸통 (§3.2 A~F) |
| **SUS** (10문항) | 단일 시스템 사용성 | **부적합.** 두 조건이 셸을 공유해(as-built §0) SUS 차이는 안 나오고, 나오면 셸이 아니라 기능 부재를 잰 것. 권장 X |
| **CSI** (Creativity Support Index) | 창작 도구 | *Expressiveness*·*Results Worth Effort* 두 요인만 차용 |
| **신뢰 척도** (Hoffman XAI trust 8 — PromptHive) | 신뢰 다차원 | 여기선 T1 한 문항 + 예측가능성 지각 1문항이면 충분(신뢰는 RQ2 병치 지표) |
| **TAM** (유용성·용이성) | 채택 예측 | Replay_Quality에서 업무 일반 TAM 12를 이미 받음 — 재측정 X. 용이성 1~2문항은 **패리티 확인용**으로 유용 |
| **채택 의향·선호** | 흔함 | 기술통계만(설계 v2 §7 — 조건이 가려지지 않아 demand 노출) |
| **자유서술** | 2~3개 | 인터뷰가 있으므로 2칸 이내, 인터뷰 **전에** 타이핑 |

### 3.2 문항 은행 (구인별 · EN 원문 + 국문 · 출처/역할)

**형식(말미).** side-by-side grid — 행 = 진술, 열 = *First version* / *Second version*, 7점(1 = Strongly disagree … 7 = Strongly agree). 라벨은 "first/second"가 참가자에게 가장 명확하고, 셀 표로 조건에 매핑한다. 화면 특징 라벨("the version with intents / with the Rules document")도 가능 — 지칭이지 편향이 아님(문항지 §0 원칙).

**지시문(말미)** — EN: *"You used two versions today. For each statement, please rate the first version and the second version separately. There are no right answers — we want your honest impression."* / 국문: "오늘 두 버전을 사용하셨습니다. 각 진술에 대해 첫 번째 버전과 두 번째 버전을 따로 평가해 주세요. 정답은 없습니다 — 솔직한 인상을 듣고 싶습니다."

**A. 저작 경험 — 기존 문항 유지 (설계 v2.1 '주관 지표')**

|---|---|---|---|

| # | EN | 국문 | 비고 |

### 3.3 권장 세트와 시간

- **블록 안** (블록 테스트 UI 마지막 화면, 각 ~30초): **B1 · B2**.
- **말미** (인터뷰 직전, ~4분 [파일럿 실측]):
  - side-by-side 진술 **12개** × 2 버전 = 24 평정 — **C1 C2 T1 · E1 E2 O1 · L1 L2 L3 · P1 · V1 · U2**
  - 양극 비교 **5개** — I1~I5
  - 자유서술 **W1** (두 칸)
- **빼도 되는 것**(시간·피로에 따라, 이 순서로): U3 → E3 → S1 → P2 → U1 → B3 → A1 → I6 → W2. (U3는 패리티 증거로 가치가 있으니 시간이 되면 살린다.)
- **인터뷰 도입에서 짚기** (런북 §3.7 도입 뒤): ★ EN *"Before we start — you rated the {first/second} version {quite low/high} on '{statement}'. Tell me about that."* / 국문: "시작 전에 하나만요 — {첫/두} 번째 버전에 '{진술}'을 {꽤 낮게/높게} 주셨는데요. 그때 상황을 말씀해 주시겠어요?" — 극단값·두 버전 간 큰 차이·역문항 불일치에서 고른다.

### 3.4 하지 말 것

- 진술형에 "better / easier than the other" 같은 **유도 문구**를 넣지 않는다 — 비교는 I군에서만, 양극으로.
- 시스템 이름·조건명(SCORE, baseline, treatment). "the first/second version" 또는 화면 특징.
- SUS 그대로 · TAM 재측정 · 문항 30개 이상(85분 시점 피로 → straight-lining).
- **유의성 주장** — N=16 · 자작 문항 · 조건 비-블라인드. 기술통계 + 효과크기 + 분포 그림(Co-Evolution Fig. 10 스타일 diverging bar; 두 버전 나란히). 탐색적 Wilcoxon은 가능하나 확증 주장 없음(설계 v2 §7 분석 원칙 그대로).
- 지각 예측가능성(P1)·귀속 지각(L3)을 RQ2 결과처럼 쓰기 — 반드시 *perceived*로 표기하고 실측(V1~V3)과 병치. 갈림이 나오면 그것이 발견이다(IOED — Chromik 2021; Kulesza 2012 "convinced themselves they were correct").
- 채택(A1·I6)·선호 비율을 근거로 쓰기 — 인터뷰의 이유·걸림돌만 코딩(설계 v2 §7 · 문항지 §0.5).

## 5. 다음 파일럿에서 볼 것

- 말미 24 + 5 + 2가 **4분** 안에 들어오는가 · 피로로 straight-lining이 나오는가(역문항 L2와 짝 문항 L1의 불일치로 감지).
- 첫 버전을 평정하며 **"잘 기억이 안 난다"**는 말이 나오는가 → 나오면 각 버전의 **최종 설정 화면 스크린샷**을 설문 옆에 띄우는 보조를 검토(회상 단서; Pass 2 재표시와 같은 원리).
- 블록 안 부담 2문항이 테스트 흐름을 끊는가 — 끊는다면 말미로 통합(§0-2의 대안).
- 인터뷰 도입의 "설문 답 짚기"가 Q1(차이)과 겹쳐 시간을 잡아먹는가 → 겹치면 Q1을 그 문장으로 대체.
